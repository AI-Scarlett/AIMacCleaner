# TraceFence Sentinel

This is the shared iOS client for both TraceFence macOS distribution lines:

- Mac App Store build: Apple subscription unlocks Standard remote control.
- Website build: Dodo Payments Standard monthly or annual license unlocks remote control.

The iOS app does not talk to a TraceFence backend. It connects directly to the paired Mac, preferring the independently updatable Agent Core gateway on port `17896` and falling back to the macOS compatibility gateway on port `17895`.

Session presentation is intentionally compact and deterministic. Monitor and Sessions use an Agent -> project hierarchy, hide agents without a currently detected app or CLI, keep only the newest conversation for each normal project, retain unprojected conversations for three days, and replace completed automation runs with the next active schedule occurrence. Alerts and non-actionable failures expire from the Approvals tab after 24 hours; unresolved permission requests remain until they are handled.

## Build

```sh
cd TraceFenceIOS
xcodegen generate
xcodebuild -project TraceFenceIOS.xcodeproj -scheme TraceFenceIOS -configuration Debug -destination 'generic/platform=iOS Simulator' build
```

Create a signed archive:

```sh
xcodebuild -project TraceFenceIOS.xcodeproj \
  -scheme TraceFenceIOS \
  -configuration Release \
  -destination 'generic/platform=iOS' \
  -archivePath ../build/TraceFenceSentinel-iOS.xcarchive \
  archive \
  -allowProvisioningUpdates
```

Export an App Store Connect IPA after the App Store provisioning profile is available locally:

```sh
xcodebuild -exportArchive \
  -archivePath ../build/TraceFenceSentinel-iOS.xcarchive \
  -exportPath ../build/TraceFenceSentinel-iOS-AppStore \
  -exportOptionsPlist ../AppStoreExportOptions.plist \
  -allowProvisioningUpdates
```

## Pairing Flow

1. Open TraceFence on the Mac.
2. Click the iPhone remote pairing icon in the lower-left corner of the Mac app.
3. Enable the Mac Local Control API in the pairing popover.
4. Copy iOS pairing information.
5. Scan the QR code from the iOS app Pairing tab, or paste the copied pairing JSON and tap Import and Test.

The pairing payload includes:

- Mac endpoint
- Pairing token
- Mac distribution channel
- Local addresses
- No-backend connectivity requirements

## Implemented API Surface

The iOS client currently calls:

| Endpoint | Purpose |
| --- | --- |
| `GET /v1/status` | Fetch Mac app, subscription, gateway, disk, hardware, and monitoring status. |
| `GET /v1/agents` | Fetch active Agent sessions, pending approvals, and the recent activity timeline. |
| `GET /v1/sessions` | Fetch the paged cross-Agent project and session catalog. |
| `POST /v1/sessions/context` | Fetch semantic recent turns with stable turn IDs and bounded tool history. |
| `GET /v1/events` | Fetch a longer event timeline for Agent activity. |
| `GET /v1/approvals` | Fetch only pending permission, question, and plan approvals. |
| `POST /v1/approvals/approve` | Approve a pending operation and resume the waiting Agent continuation. |
| `POST /v1/approvals/deny` | Deny a pending operation, question, or plan. |
| `POST /v1/sessions/launch` | Launch an installed CLI Agent through a TraceFence-owned PTY. |
| `POST /v1/sessions/relaunch` | Start a new TraceFence-owned PTY continuation from a monitored task that has a known installed CLI target. |
| `POST /v1/sessions/interrupt` | Pause an attached Agent process from iOS when the Mac session has a controllable pid. |
| `POST /v1/sessions/resume` | Continue a previously paused Agent process. |
| `POST /v1/sessions/terminate` | End a TraceFence-owned or safely attached Agent process. |
| `POST /v1/monitor/start` | Start Mac monitoring. |
| `POST /v1/monitor/stop` | Stop Mac monitoring. |

All non-health requests require the Bearer pairing token generated by the Mac.

## Control Capability Contract

The iOS client does not guess whether a task is controllable. It follows the Mac response fields:

- `controlMode`: `tracefence_pty`, `hook_question`, `hook_approval`, `process_group`, `process_tree`, `single_process`, or `display_only`.
- `controlAvailable`: whether this row has any real control path.
- `canInterrupt`, `canResume`, and `canTerminate`: button enablement.
- `resumeRequiresInstruction`: whether the Continue sheet must collect a user instruction.
- `canRelaunch`, `relaunchTargetId`, `relaunchTargetName`, and `relaunchInstruction`: whether Sentinel can start a new controllable PTY continuation for an observed display-only task.
- `controlReason`, `controlLimitations`, and `deliveryModes`: user-facing explanation and technical delivery path.

Rows marked `display_only` are observation snapshots from logs, databases, GUI apps, or stale process discovery. Sentinel must keep their interrupt/continue controls disabled.

## Internet Remote Control Requirements

TraceFence does not operate a relay. For Internet access, users must provide one of:

- Private VPN / tailnet such as Tailscale, ZeroTier, WireGuard, or company VPN.
- Port forwarding plus DDNS or static IP.
- User-owned reverse tunnel such as Cloudflare Tunnel, frp, SSH reverse tunnel, or VPS relay.

Plain HTTP should only be used on trusted local/private/tailnet networks. Public endpoints should be protected by HTTPS or a secure tunnel.

## Agent Control Notes

- Permission, question, and plan approvals use the Mac HookServer continuation path, so the waiting Agent can actually continue after the iOS approval.
- CLI Agents launched from Sentinel use the Mac TraceFence PTY runner. TraceFence owns the terminal, can write instructions, and controls the process group.
- Session interrupt/resume depends on the Mac reporting a safe control mode. Process signals only pause or resume execution; they do not rewrite the Agent's conversation state.
- Sending a new instruction requires Hook waiting input, a writable tty from a TraceFence-owned/recognized terminal session, or a future Agent API adapter.
- TraceFence still does not operate a cloud relay. Internet control depends on the user's VPN, tailnet, reverse tunnel, or forwarded endpoint.

## Security, Refresh, And Notifications

- Face ID, Touch ID, or the device passcode protects app launch, return from background, and pairing changes through `deviceOwnerAuthentication`.
- The connection store races saved, last-known, Bonjour, LAN, VPN, and manually configured endpoints and remembers the route that most recently succeeded.
- Every tab exposes the current connection state. Settings shows the active route and last successful refresh time.
- Local notifications cover approval requests, new Agent replies, task completion, and ended sessions. Notification taps open the appropriate Approvals or Sessions tab.
- With no TraceFence backend there is no APNs relay while iOS fully suspends or terminates the app. Sentinel catches up missed state when it remains connected or is reopened and explains this limit in Settings.
- The Sessions detail screen displays the most recent three semantic turns and can page backward three turns at a time. Tool-heavy turns are compacted by Core to keep scrolling responsive.

## Store Note

`ITSAppUsesNonExemptEncryption` is `false` because Sentinel uses only Apple-provided networking and standard transport security. ATS currently permits user-owned local, tailnet, and tunnel endpoints; public exposure should still use HTTPS or a private VPN.
